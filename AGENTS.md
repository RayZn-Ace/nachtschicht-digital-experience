
- Lounge availability (cards, floorplan, event page) goes through `useLoungeAvailability` + `src/lib/loungeAvailability.ts`; floorplan geometry maps stable lounge IDs in `src/lib/loungeFloorplans.ts` — one rule source, and unknown/error never renders as bookable.
- Floorplan backgrounds live in `public/images/floorplans/` (versioned names); hotspot geometry in `loungeFloorplans.ts` uses each image's native pixel space so the SVG overlay stays aligned at any width.
- Checkout discount lookup uses the exact-code `validate_discount_code` RPC returning only discount terms; never reopen public discount-table reads to repair checkout.
- Newsletter list sends paginate membership, fetch subscriber IDs in small chunks, claim campaigns atomically, and use idempotent provider batches with per-recipient history to avoid truncation, timeouts, and duplicate sends.
- Ticketcenter paginates all metadata and ticket reads with stable ordering and rejects partial results; scanner short IDs use UUID range bounds, never cast filters or capped recent-ticket scans, to avoid missing older tickets.
- Ticketcenter bounds each read page, cancels superseded loads and publishes only complete batches; render sales in 100-row pages while searches, totals and exports retain the entire loaded dataset, avoiding thousands of simultaneous DOM rows.
- Other ticket/history/report readers use fetchCompleteResult or fetchAllRows with stable ordering and fail-closed publication; PagedItems portions display only, never search/export/statistics, and uses table rows for table pagination. Live check-in refresh waits for its current load to finish.
- Cancellation response quantities are derived from the cancelled ticket rows by a pure summary helper; sold-count updates stay exclusively in the database trigger to avoid double restoration.
- Install the bounded backend-read fetch before App imports the data client; only GET/HEAD data reads and explicitly read-only RPCs have deadlines, with a visible failure notice. Never automatically retry or abort payment/order/email writes because their outcome may already be settled.
- Auth initializes roles once per user identity, not on same-user focus/token events; initialization failures block login redirects rather than treating an unverified staff role as a customer. Keep SDK locks intact and bound only UI waiting on password sign-in, without automatic retries.
- Session reads for scanner synchronization, newsletter sending and recovery use getSessionBounded; timeout must stop before writes, preserving queues and settled records. Account data effects depend on user ID rather than refreshed user objects.
